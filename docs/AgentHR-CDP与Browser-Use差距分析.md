# AgentHR CDP 与 Browser Use 差距分析

## 1. 结论

AgentHR 当前实现是“招聘域专用的安全浏览器执行层”，Codex 的 Browser 插件是“通用浏览器自动化平台”。两者都使用 CDP，但目标不同：

- AgentHR 优先保证招聘平台范围、候选人数据边界、动作可审计和敏感操作默认阻断。
- Codex Browser 优先覆盖任意网页任务，提供无障碍树、Playwright、截图/坐标操作、标签页、文件、弹窗和可选 CDP 等多层能力。

因此不建议用通用 Browser Use 整体替换 AgentHR。更合理的方向是保留 AgentHR 的权限门、平台适配器和业务技能，在底层吸收 Browser Use 的观察、等待、视觉兜底和操作回执能力。

## 2. 比较对象

### AgentHR 当前实现

核心代码：

- `src/main/cdp-browser.ts`
- `src/main/adapters/browser-use.ts`
- `src/main/recruitment-browser.ts`
- `src/plugin/index.ts`

当前链路：

```text
Agent
  → agenthr_browser_snapshot
  → CDP 读取 DOM + Accessibility + iframe
  → 返回带签名的临时 ref
  → agenthr_browser_action(ref, 固定动作)
  → 动作前重验签名、可见性、遮挡和权限
  → 原生 CDP Input 事件
  → Agent 重新读取快照验证业务结果
```

### Codex Browser / OpenAI Computer Use

本机随附的 Codex Browser 插件包含：

- 无障碍树优先的读写接口。
- Playwright locator 和自动等待。
- 截图与坐标式 CUA 兜底。
- DOM CUA、开发检查能力和受限原始 CDP。
- 标签页、导航、弹窗、剪贴板、文件上传、下载/内容导出和人工接管。
- 浏览器级、标签页级可发现 capability。

OpenAI 官方文档也把 computer use 定义为模型可用工具能力；Responses API 中的 computer tool call 使用结构化动作并以截图作为工具输出的一部分：

- https://developers.openai.com/api/docs/guides/latest-model
- https://developers.openai.com/api/reference/cli/resources/beta/subresources/responses

## 3. 能力对照

| 维度 | AgentHR CDP | Codex Browser Use | 判断 |
| --- | --- | --- | --- |
| 页面范围 | 只允许当前 BOSS/猎聘 WebContents 和同站框架 | 面向通用网页、多浏览器和多标签页 | AgentHR 更安全，通用性较弱 |
| 观察方式 | DOM 控件、完整层级 AX 树、增量 diff、受控截图诊断 | AX 主路径、DOM、截图、视觉坐标、按需开发检查 | 基础观察能力已补齐；AgentHR 仍不开放截图坐标点击 |
| 元素引用 | 快照内临时 ref + 节点签名 + URL 版本 | AX index、Playwright locator、DOM/CUA、坐标 | AgentHR 的过期保护好；定位策略较单一 |
| iframe | 支持同站 iframe 和 OOPIF 自动附着 | Playwright frame、OOPIF、截图坐标等多条路径 | 两者都有基础，Codex 的回退路径更完整 |
| Shadow DOM | 扫描 open shadow root | Playwright 注入和 locator 体系 | AgentHR 只覆盖 open shadow root |
| 动作 | click、hover、fill、select、Enter、上下滚动 | 额外支持组合键、文本选择、拖拽、坐标动作、文件选择等 | AgentHR 动作集合明显不足 |
| 等待与重试 | 结构化等待条件、最长 8 秒 deadline、动作回执；失败后仍由 Agent 诊断 | locator 自动等待、严格模式、deadline、重试和事件等待 | 已有安全等待基础，仍缺 locator 级自动重试 |
| 视觉验证 | 截图进入隔离视觉子 Agent，主 Agent 只接收结构化结论 | 可按需取截图，并在 AX 失效时用坐标操作 | AgentHR 可诊断纯视觉状态，但不直接坐标点击 |
| 导航和标签页 | 每个平台一个受控会话，固定页面入口 | 创建、选择、认领、关闭、前进后退、刷新标签页 | AgentHR 是有意收敛，但弹窗/新页流程能力不足 |
| 文件与弹窗 | 下载和上传默认阻断 | 文件 chooser、内容导出、JS dialog、人工接管 | 招聘附件场景尚未形成受控流程 |
| 敏感动作 | 标签正则阻断 + 独立高风险业务工具 | 通用确认策略 + capability 边界 | AgentHR 的业务边界更强，但正则识别需要加强 |
| 数据抽取 | BOSS/猎聘专用卡片与简历解析器 | 通用页面读取，不理解招聘字段 | AgentHR 明显更强 |
| 审计 | 招聘任务、人才、技能和事件持久化 | 主要是通用工具调用状态 | AgentHR 更贴近业务合规 |
| 工作流沉淀 | 自动提取/合并草稿、版本化运行、步骤断点、Agent 回退和 `needs_repair` | 通用工具与技能/指令体系 | 已形成业务闭环，仍缺审核后发布到 DSH Skill Manager |

## 4. AgentHR 已经做得好的部分

### 快照过期保护

动作必须携带最新 `snapshotId`，页面 URL、元素 ref 或签名变化都会拒绝执行。这比让模型长期保存 CSS selector 更可靠，也能防止 React 重渲染后误点另一个节点。

### 真正的输入事件

点击、键盘和文本输入通过 CDP `Input` 域发送，并检查元素是否可见、是否被遮挡，以及可信点击事件是否到达目标。它比直接执行 `element.click()` 更接近真实用户操作。

页面中的彩色指针属于独立展示层，不是输入源，也不能作为动作成功证据。动作回执会分别记录实际派发通道（`cdp_input` 或 `dom_api`）、是否属于可信输入，以及展示指针的目标位置；指针在真实派发发生后才进入 `dispatched` 状态。当前通用点击、悬停、输入和回车，以及打开候选人详情、关闭 BOSS 详情和 BOSS 打招呼三个专用流程，均由同一 CDP 可信输入执行器派发并确认 `isTrusted` 点击；业务适配器只负责重新匹配唯一目标，不再自行调用 `element.click()`。原生下拉选择与平滑滚动仍走受控 DOM API。

### 页面和权限收敛

CDP 仅附着到 AgentHR 自己的招聘 WebContents；URL 必须属于当前招聘平台域名。模型拿不到任意 CDP 命令、任意 selector 或任意脚本执行入口。

### 招聘语义能力

通用 Browser Use 能打开页面，却不知道什么是“候选人线索”“唯一可见简历”“岗位关联”或“禁止重复打招呼”。这些领域能力是 AgentHR 的核心壁垒，应该继续由平台适配器和招聘技能承载。

## 5. 关键差距

### 5.1 缺少视觉观察与坐标兜底

当前快照对 canvas、图片文字、无标签图标、复杂虚拟列表和纯视觉选中状态无能为力。现已增加受控视觉诊断：当前可见视口截图只发送给隔离的一次性视觉子 Agent，主 Agent 仅接收结构化结论、置信度、遮挡类型和建议的下一步，不接收图片内容块。视觉分析结束后立即物理删除本机规范化原图与模型请求变体；进程异常中断时由 15 分钟租约和周期垃圾回收兜底。坐标动作仍需经过当前域名、风险和遮挡校验。

### 5.2 无障碍树基础已补齐

当前已保留 AX 层级、关键状态、value、disabled、selected，并在首次完整快照后返回有边界的 added/changed/removed 增量。下一步仍需继续压缩大型虚拟列表，并让更多平台适配器优先消费 AX 语义。

### 5.3 已增加结构化等待，仍缺 locator 级自动重试

当前动作支持 URL 变化、目标出现/消失、值变化、选中状态变化和文本变化等有限、可审核的等待条件，并把验证结果写入动作回执。仍需在可信运行时内部增加 locator 级重试；等待条件继续来自结构化动作定义，不接受模型脚本。

### 5.4 操作原语不够

招聘网站会遇到组合键、分页、虚拟列表、拖拽滚动条、文本选择、文件 chooser 和新窗口。需要按真实需求逐步增加固定动作，不开放任意 CDP。

### 5.5 步骤级执行回执已接入技能运行

动作回执区分输入是否派发和预期变化是否验证，并记录前后状态、证据、耗时和失败分类。技能运行进一步保存 pending/running/completed/failed/skipped 状态；失败证据形成恢复断点并自动回退 Agent。

### 5.6 权限识别仍依赖文本正则

“发送”“联系”“下载”等标签可以识别大多数按钮，但平台换文案或只显示图标时可能漏判。应把平台适配器识别出的业务动作类型与 DOM 标签规则合并；高风险能力使用一次性授权令牌，而不是仅靠按钮文字。

## 6. 建议架构

```text
招聘技能层
  参数、步骤、成功标准、失败回退、版本
        ↓
招聘语义层
  搜索候选人、打开详情、保存人才、分析、沟通授权
        ↓
安全动作层
  固定动作 schema、快照版本、风险分类、授权令牌、动作回执
        ↓
Browser Runtime
  AX 主路径 + DOM/ref + 自动等待 + 截图诊断 + 有限坐标兜底
        ↓
受控 CDP
  当前 WebContents、域名白名单、OOPIF、原生输入事件
```

模型仍然只产生业务意图和结构化动作。selector、Playwright locator、脚本和 CDP 命令即使在可信运行时内部使用，也不暴露给模型，更不会写入招聘技能。

## 7. 推进顺序

### P0：补稳定性与证据

- [x] AX 树保留层级和关键状态，并支持快照 diff。
- [x] 增加截图只读诊断；图片只进入隔离的一次性视觉子 Agent，主 Agent 仅接收结构化结论；登录页禁用。
- [x] 增加结构化等待条件和动作回执。
- 增加 `press_key`、定向滚动和滚动容器识别。
- 每个技能步骤保存开始、完成、失败和证据。

已实现的等待条件包括：控件值、控件状态、控件出现/消失、文本出现/消失、URL 路径匹配和 URL 变化。等待最长 8 秒；超时返回 `done=true, verified=false`，明确表示输入已发送但业务结果尚未验证，避免 Agent 机械重试。

动作回执包含唯一回执 ID、动作目标、前后 URL 路径、前后控件状态、输入派发时间、等待证据和总耗时。截图仅覆盖当前受控招聘页面的可见视口，限制尺寸和字节数，不提供登录页画面，也不开放截图坐标点击接口。截图经临时附件租约交给零工具权限的一次性视觉子 Agent；主会话的工具结果只有页面摘要、可见观察、遮挡类型、置信度、建议下一步、截图摘要和已删除回执，不包含图片或附件 ID。每张内部截图写入不可见的随机像素标记以获得独立内容地址，避免删除时影响相同内容的其他附件；正常路径在工具返回前删除，失败和取消路径同样执行清理，遗留租约最多保留 15 分钟。

### P1：补复杂页面适应能力

- 可信运行时内部引入 locator/自动等待，不让模型生成 selector。
- DOM/ref 失败时使用截图定位建议，由安全动作层重新校验。
- 支持弹窗、新窗口和文件 chooser 的受控流程。
- 建立 BOSS、猎聘页面能力矩阵和回归样本。

### P2：工作流沉淀与自愈

- [x] 成功任务抽取技能草稿并按流程指纹去重合并。
- 稳定步骤升级为确定性执行器。
- [x] 失败时记录断点并回退 Agent；连续三次失败标记 `needs_repair`。
- Agent 给出结构化修订，沙箱验证后由用户发布新版本。
- 审核后的 AgentHR 技能发布到 DSH Skill Manager，草稿不直接进入模型可调用目录。

## 8. 不建议照搬的能力

- 不向模型开放原始 CDP。
- 不允许模型持久化任意 selector 或脚本。
- 不为招聘任务提供任意站点导航。
- 不把坐标点击作为默认路径。
- 不把验证码、登录、下载、上传或候选人沟通混入普通动作接口。

这些限制会减少通用性，但能避免技能在页面变化后静默误操作，也便于对候选人数据和对外沟通建立稳定的审计边界。
